=== SMOKE RUN 1 FAILURE AND RESOLUTION ===
The first US12 smoke version changed availability through US6's real API and UI:
  x HTTP  US12 ... -> AssertionError: expected 503 to be 200 (PATCH /api/wardrobe/[id]/availability)
  x Browser US12 ... -> Timed out waiting for: My Wardrobe ("We couldn't load your wardrobe")
  x Browser: offers Try again ...; mobile layout ...; offers Sign in ... -> knock-on failures: the
    US12 browser test stopped on the wardrobe page, so the next tests ran on the wrong page.
Cause: an environment limitation of the smoke setup, not a US12 or US6 defect.
getProductionWardrobeItemService() needs Cloudinary settings and fails closed without them; the
smoke test blanks CLOUDINARY_* on purpose (BLANK_SECRETS), so every wardrobe API answers 503 there.
The 503 rejected the change, so no data was altered.
Resolution: no fake Cloudinary settings were added (instruction: don't change Cloudinary
configuration). The two US12 smoke tests change the seeded item's availability directly in the
temporary MongoDB (and restore it in `finally`). US6's real availability API together with
generation is verified by tests/integration/api/insufficientWardrobe.test.ts (Checkpoint 2).
