=== WHAT THE NEW TESTS VERIFY ===
Integration (insufficientWardrobe.test.ts). One MemoryWardrobeItemRepository (US6's test store,
which also implements listAvailableByOwner) backs both US6's real handleSetAvailability handler
and OutfitRecommendationService behind handleGenerateOutfit. Requests carry real sessions from
AuthService, CSRF origin headers, and JSON bodies.
 1. Insufficient -> available -> outfit: Alex's needed Bottom is marked unavailable through
    PATCH /api/wardrobe/[itemId]/availability, so generate gives insufficient/no_complete_outfit.
    After it is marked available again, generate gives an ok outfit [top, bottom] with Alex's
    item IDs. Sam's available Bottom (which would complete the outfit) never appears.
 2. Same flow for no_suitable_items: the only Formal item (a dress) is unavailable, then available.
 3. Another user's items or availability change don't complete the signed-in user's outfit.
 4. x5 (each occasion): with Alex's available and unavailable items and Sam's items in every
    category and formality, every recommended ID is one of Alex's saved, available items, and
    its image URL, category, and formality equal the stored record (nothing filled in).
 5. x3: top without bottom / bottom without top / only optional pieces -> exactly
    { status: 'insufficient', occasion, reason: 'no_complete_outfit' }, with no `items`.
Unit (generateOutfit.test.ts, "insufficient wardrobes (US12)"):
 6. x64: every combination of the six categories, alongside an unavailable item and another
    user's item of every category. Without a Dress or a Top+Bottom, the result is exactly
    insufficient (no_suitable_items when the user has no eligible items, else no_complete_outfit).
    Otherwise every piece is one of the given objects (none created or copied), no item repeats,
    and the core is exactly [dress] or [top, bottom], never a lone top or bottom.
Component (CreateOutfitForm.test.tsx):
 7. After an insufficient result, the links are present, the occasion stays selected, and
    Generate Outfit is enabled. Generating again sends the same occasion; the outfit replaces the
    insufficient message and explanation; the occasion is still selected.
 8. While generating again, the old explanation is hidden (only the button's "Loading..." status
    remains). A second insufficient answer shows its own new reason, not the old one, with the
    links.
