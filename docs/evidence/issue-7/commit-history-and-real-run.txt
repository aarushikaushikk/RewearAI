== 3. Real run: real Cloudinary, throwaway database ==
Setup: `next start` on http://localhost:3002 (the rewear-dev-memdb launch config), MONGODB_URI pointed at a
temporary in-memory MongoDB on 127.0.0.1:27999. Cloudinary keys and CRON_SECRET came from .env.local.
A test account was created on that temporary database through /sign-up.

1. /wardrobe/new shows "Drag a photo here, or choose one below." and marks My Wardrobe current.
   Screenshot: screenshots/add-clothing-drop-zone.png
2. A browser DragEvent with a 400x500 JPEG made on a canvas:
   dragover -> the area gets the dashed highlight
   drop     -> preview shown; POST /api/uploads -> 201 Created; "Image uploaded." announced
3. Filled Category Top, Color Green, Season All-season, Formality Casual, Style Crew-neck tee; saved.
   POST /api/wardrobe -> 201 Created; success card shows "Green Crew-neck tee", Top · All-season · Casual, Available.
   The card's image is served from https://res.cloudinary.com/<cloud>/image/upload/v…/rewear/users/<id>/<file>.jpg
   Screenshot: screenshots/saved-item-from-cloudinary.png
4. GET /api/cron/cleanup-uploads with `Authorization: Bearer $CRON_SECRET` -> {"success":true,"data":{"deleted":0,"confirmed":0}}
   (the new image is under 24 hours old, so it isn't considered yet). Without the header -> 401.
   This confirms the Cloudinary Admin API listing by tag works with the configured keys.
5. Cleanup: the test image was deleted from Cloudinary afterwards, because its database record lived only
   in the temporary database.
