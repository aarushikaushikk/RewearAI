=== WHAT THE ADAPTER GUARANTEES (each covered by a test) ===
- Creates the worker on first use and reuses it; requests carry unique IDs, so concurrent
  replies resolve the right request in any order.
- Rejects with a WorkerClassifierError code: load_failed, inference_failed, invalid_response,
  crashed, timeout, unavailable, disposed. classifyClothingImage turns any of them into
  "unavailable", which offers manual entry. Codes are for diagnostics, never shown to users.
- A crash, or a timeout, stops the worker and fails all its pending requests; the next call starts
  a new worker. Late replies and replies from replaced workers are ignored.
- Until a worker first answers it gets the longer loading timeout (default 300 s, covering the
  one-time model download); afterwards each request gets 60 s. Both are untested starting values.
- createBrowserClassifier returns null where Worker or WebAssembly is missing.

New file src/services/classification/browser/classifier.worker.ts:
1. On the first request, load Marqo/marqo-fashionSigLIP once: AutoTokenizer, AutoProcessor,
   SiglipTextModel, and SiglipVisionModel (the model card's Transformers.js example). Quantized
   download about 205 MB plus about 27 MB of ONNX Runtime WASM, kept in the browser cache.
2. Embed the prompt labels once (padding: "max_length") and cache the embeddings for those labels.
3. For each image: RawImage from the Blob or URL, processor, vision model, then
   scoreLabels(imageEmbedding, labelEmbeddings, labels) from zeroShotScoring.ts.
4. Reply { type: "result", id, scores }, or { type: "error", id, code } with load_failed or
   inference_failed. Never post raw error details.
