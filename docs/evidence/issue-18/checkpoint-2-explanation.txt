=== BEHAVIOUR ===
Only facts cross the API; the page writes every sentence, so server text never reaches the user.
A missing or impossible `explanation` shows the outfit without the panel.
Why these items? shows:
  - a reason line from the generator's real rules (formality, season, palette);
  - a stylist note: a mood sentence (palette x vote of the pieces' saved styles) and a piece
    sentence for one featured piece. The featured piece rotates on Try another.
If US3's FashionSigLIP files are already in the browser cache, the item photos may change the
wording and the featured piece, only among options consistent with each saved style (AGENTS 5).
"Styling note chosen with on-device AI from your saved item details and photos." appears only when
they changed something. Create Outfit never starts the ~205 MB download. Any model failure or
timeout (10 s) keeps the basic note with no error.
Every library sentence is hedged (can, may, tends to), has none of perfect/ideal/best/always/must/
definitely/stunning, claims no learning, and names no garment, fabric, weather, place or occasion
of its own; stylistLibrary.test.ts checks every sentence.

=== FINDING DURING THE CHECKPOINT: ONE SHARED PHOTO PROMPT SET WAS NOT GOOD ENOUGH ===

one shared label set ("a photo of {vibe} clothing"): the saved style was in SigLIP's top three for
14 / 23 (61%), below the 65% bar. Per-role prompts ("a photo of a {vibe} jacket") gave 16 / 23 (70%)
at ~150 ms per photo on a laptop CPU, so 0d94925 uses per-role prompts and the classifier worker keeps
up to 8 label sets, so each role's text is embedded once per tab.
