=== BEHAVIOUR ===
Before: an uncertain suggestion was marked only by grey hint text ("Needs review. Confirm or change
this suggestion.") and its "<value> is correct" checkbox. A save blocked by unreviewed suggestions
showed field errors only.
After:
- A field whose suggestion still awaits review (review state `reviewed: false`) gets a
  warning border and fill (border-warning, bg-warning-soft) and warning-colored hint text. The hint
  text and checkbox are unchanged, so color is never the only signal.
- Confirming, changing, or typing a different value clears the highlight; unticking brings it back.
- Confident, missing, invalid, and manual fields keep the default look.
- A validation error always takes precedence: danger border, aria-invalid, and the error message,
  exactly as before. `warning` does not set aria-invalid.
- Clicking "Confirm and save" while suggestions are unreviewed now also shows, above the analysis
  notice, an error alert: "Review or correct the highlighted details before saving." It does not
  take focus; focus still goes to the first invalid field. It disappears once every uncertain
  detail is reviewed. It is not shown when only empty fields block the save, and not for
  suggestions that arrive after a save that was blocked only by empty fields.
- Failure, retry, not-clothing, and manual-entry behaviour unchanged (existing tests pass).
- With `warning` unset, both components render the same classes as before (bg-surface,
  border-text-muted, text-text-muted hint), confirmed by tests.

Contrast (WCAG 2.1, computed from the design tokens):

  body text on warning-soft 13.65:1; placeholder on warning-soft 5.63:1; focus ring 7.29:1.
Layout unchanged: no new elements in the field grid, so the existing 1-column (mobile) / 2-column
(sm and up) layout is unaffected.
