=== SECURITY BEHAVIOUR COVERED ===
- The CSRF origin check runs first: a cross-site request or one without Origin or Referer gets
  a 403 before the session or wardrobe is read; also tested through the real route's POST export.
- Without a session, or with a signed-out one, the answer is 401 and no wardrobe is read.
- The owner comes only from the session. The body must be exactly { occasion }: userId, ownerId
  and itemIds are rejected with 400 before any wardrobe read. The source is called once, with
  the session user's ID.
- The occasion must exactly match one of OCCASIONS. Missing, empty, differently cased, padded,
  unsupported or non-string values get 400 "Choose an occasion to continue."; a malformed body
  gets 400 "Invalid request payload".
- The MongoDB query is one find filtered by { owner, isAvailable: true } (checked with
  recordQueries). A malformed owner ID returns nothing without a query.
- Defence in depth: generateOutfit filters by owner and availability again.
- Responses contain only display fields: no ownerId, image publicId, isAvailable or timestamps.
  Another user's item IDs never appear.
- Failures: a database outage gives 503 "The outfit service is temporarily unavailable. Please
  try again later."; an unexpected error gives 500 "Internal server error". Logs contain only
  the error's name, and no driver details reach logs or errors.
