CreateOutfitForm (20):
- A required "Occasion (Required)" select with Choose… plus Work, Dinner, Weekend, Casual and
  Formal; Generate Outfit is the only button; no results at first.
- With no occasion: "Choose an occasion to continue.", aria-invalid, focus on the select, and
  no request.
- For each of the 5 occasions: POST /api/outfits/generate, JSON content type, a body of exactly
  { occasion: "<lowercase value>" }, and "Your outfit for <Label>".
- Items appear in a list named "Items in this outfit", each with its saved photo (next/image
  src contains the Cloudinary URL), a readable name and a role label. Unnamed items show color
  and style ("Navy Chinos"). All six roles have readable labels. Focus moves to the result
  heading.
- While loading: Generate shows "Loading…" and is disabled with the select; three clicks in one
  batch send one request.
- Insufficient: "There aren't enough available items for a formal outfit yet." with View
  wardrobe (/wardrobe) and Add clothing (/wardrobe/new); no item list.
- Errors (401, 503, 500, network, a success response without a usable outfit): the app's own
  message in an alert, never server text; the occasion stays selected; Try again resends the
  same occasion and shows the outfit.
- Choosing another occasion clears a shown outfit, an insufficient message or an error.
- An answer for a different occasion than requested is treated as an error, never shown under
  the wrong occasion.
Page (2): a visitor without a session is sent to /sign-in; signed in, there is one h1 "Create
  Outfit", main#main-content, the form, and the header marks Create Outfit as the current page.

Responsive: the form stacks on mobile and is one row from sm up; items are 1, 2 and 3 columns
(sm, lg) with 4:5 photo frames and 44 px minimum touch targets. jsdom has no layout, so this
was checked in code only, not in a browser.
