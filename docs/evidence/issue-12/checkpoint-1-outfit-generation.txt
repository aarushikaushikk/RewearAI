PROVISIONAL rules (approved for this checkpoint, pending teammate review):

  Formal; weekend: Casual or Smart casual; casual: Casual; formal: Formal); no mixing of
  different specific seasons, with All-season fitting anything; only the user's own available
  items, each used once; an explicit insufficient result when no outfit can be made.

=== TESTS (38) ===
occasions: the approved mapping; for each of the 5 occasions, only allowed formalities are
  used even when disallowed items come first, and an insufficient result when only other
  formalities exist; an unknown occasion throws RangeError.
structure: Top + Bottom; a Dress alone; never a Dress with a Top or Bottom; a top alone, a
  bottom alone, or only extras is insufficient; an empty wardrobe is insufficient; shoes,
  outerwear and accessory are added in a fixed order, one of each; extras are left out when
  unsuitable; a core that suitable shoes fit is preferred; still an outfit when no shoes fit.
seasons: different specific seasons are never paired; All-season pairs with any season, and the
  shared season is reported; the next compatible bottom is used; extras must match the season
  set by the pieces before them.
ownership/availability: another user's items are never used, even to complete an outfit;
  unavailable items are excluded, and used again once available; another user's or unavailable
  extras are left out.
integrity/determinism: the input objects are returned unchanged (nothing invented); no item
  appears twice, and duplicate IDs count as one; the same input always gives the same outfit;
  earlier items in the input are preferred; on 601-item wardrobes, work stays linear (fewer
  than 20 × n season reads; trying every pair would take about 180,000).
